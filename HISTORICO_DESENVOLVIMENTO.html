Fluxo normal de rebuild

# Após alterar API ou packages/:
docker compose build --no-cache api
docker compose up -d
docker compose logs -f api

# Após alterar apenas o frontend:
docker compose build --no-cache web

Reset nuclear (APAGA O BANCO)

# 1. Zerar tudo
wsl --shutdown
docker compose down -v --rmi all
docker system prune -a -f --volumes

# 2. Reinstalar dependências
npm install

# 3. Build e subida completa
docker compose build --no-cache
docker compose up -d

# 4. OBRIGATÓRIO após -v
docker exec olympus_db psql -U postgres -d olympus -c "CREATE EXTENSION IF NOT EXISTS vector;"
cd packages/db && npx drizzle-kit push && cd ../..

# 5. Repovoar banco
DATABASE_URL="postgres://postgres:postgres@localhost:5432/olympus" npx tsx apps/api/src/scripts/seed.ts

# 6. Verificar saúde
docker compose logs -f api

Pontos de Atenção Arquiteturais e de UI

22.1 Decisões arquiteturais conscientes (intencionais)

✅ Duas rotas de análise: ReAct + LangGraph — decisão intencional

/chat/stream (ReAct, produção) e /chat/stream/graph (LangGraph, experimental). LangGraph aguarda feature parity antes de substituir a rota principal. Arquitetura consciente, não problema.

✅ App.tsx com estado global centralizado — padrão deliberado para MVP

Decomposição em contextos React está no roadmap mas não é bloqueadora para entrega. Candidato a refatoração após deploy e primeiro contrato.

22.2 Débito técnico conhecido

export.ts — mapeamentos duplicados

PHASE_LABELS/PHASE_COLORS em buildHtml() e DOCX_PHASE_LABELS em buildDocx() devem ser mantidos em sincronia. Candidato a unificação.

parseScenarioProbabilities() — regex frágil para retrocompatibilidade

tool_register_scenario (Sprint 18) substitui para novas análises. A regex permanece para análises antigas.

HERMES_SIPLEX no banco — cosmético

Agente inativo, não recriado pelo seed. Não causa problema operacional. Pode ser apagado manualmente se necessário.

22.3 UI/UX — itens pendentes de design

Modo passos supervisionado — sem painel visual dedicado

O orquestrador apresenta [PLANO DE FASE] e aguarda confirmação inline na conversa. Falta painel visual para o estado "aguardando aprovação".

Seletor de reportLayout ausente da UI

Modo extended pronto no backend (body.reportLayout), sem controle visual na UI.

vizMode não comunicado ao usuário

Diferença entre etapa (autônomo), passos (HITL), passagem (contínuo) e thinking não é clara na interface.

EventsPanel (HITL) — sem design polido

Funcional, sem theming consistente com o restante da UI.

SIPLEx/CEEEx — não testada end-to-end após Sprint 17

Configurada com HERMES + agentMethodPrompts desde Sprint 17, não validada em análise completa após a migração de HERMES_SIPLEX.
