1.3 MSEF — posição arquitetural
A MSEF não é uma metodologia clássica — é a abordagem agêntica multimodal do Olympus. Os prompts MSEF v2 já implementam essa visão: HERMES direciona o raciocínio conforme as características da pergunta estratégica. Permanece no catálogo como metodologia par para Cenários Prospectivos, com sua lógica preservada.

3.1 Fluxo de ativação (novo vs atual)
Atual — getOrSeedMethodology()
POST /api/v1/chat → runAnalysis()
  └─ getOrSeedMethodology(name)
       ├─ if MSEF → upsert agentes MSEF
       ├─ if ALTA → upsert agentes AltA + técnicas SAT
       ├─ if GODET → upsert agentes GODET
       └─ (GRUMBACH/SIEx → só no seed.ts)
Novo — loadMethodology() — Sprint 1
POST /api/v1/chat → runAnalysis()
  └─ loadMethodology(slug)        ← leitura pura, sem upsert
       ├─ methodology_phases       ← fases ordenadas do banco
       └─ agent_method_prompts     ← extra_instructions por agente
  └─ Agent.run()
       └─ systemPrompt = base_prompt + extra_instructions
⚑ ATENÇÃO  getOrSeedMethodology() permanece comentado como fallback até Sprint 3 confirmar estabilidade.

7.1 Regras críticas — nunca violar (do HISTÓRICO)
Zod não entra no Agent.ts — schemas são TOOL_JSON_SCHEMAS (objetos JS puros)
stopWhen: stepCountIs(N) — nunca maxSteps (ignorado silenciosamente no SDK v6)
prepareStep para toolChoice — nunca toolChoice: required global (bloqueia síntese)
CMD em produção aponta para dist/index.js — nunca tsx no Dockerfile
Prompt do HERMES sem blocos de isenção de ferramentas
docker compose down -v apaga o banco e os modelos Ollama — usar sem -v em operação normal
Ferramentas que importam @olympus/db ficam em apps/api/src/tools/ — não em packages/tools/
Rebuild obrigatório após alterar packages/core: docker compose build --no-cache api
