Contexto de Negócio

O que é o OLYMPUS: Plataforma integrada de planejamento estratégico e monitoramento contínuo. O motor ATHENA é o produto-âncora — especializado em Strategic Foresight (cenários prospectivos). O motor KRATOS cuida do monitoramento automático de indicadores.

OLYMPUS
├── Motor ATHENA → produção de cenários · 9 agentes · 7 metodologias (MSEF · GRUMBACH · GODET · MACROPLAN · MPO · ASPLAN · FUTURES)
├── Motor KRATOS → monitoramento contínuo · indicadores · alertas
├── Painel Cliente → acesso remoto · semáforo de cenário · histórico
├── API OLYMPUS → integração com parceiros · webhooks n8n
└── Vault de Dados → dados do cliente · dados abertos · offline

  • Custo < R$ 1.500/mês até o segundo contrato
  • Clientes de defesa e governo exigem: marca d'água CONFIDENCIAL, logs de auditoria, operação offline/air-gapped
  • Produto-âncora: R$ 80K–250K por projeto de cenários
  • Recorrente: R$ 8K–25K/mês (monitoramento KRATOS)
  • Meta Ano 1: R$ 300K · Exit: aquisição por Big Tech em 8 anos
  • O Playbook MSEF é o principal ativo de Propriedade Intelectual

3.3 Por que TypeScript e não Python

Python é a língua franca para treinar modelos. TypeScript é superior para construir produtos web que orquestram LLMs comerciais:

  • Unificação absoluta: Frontend, backend e banco compartilham linguagem e tipagem
  • Vercel AI SDK: Estado da arte em orquestração UI/IA — streaming, tool calling, multi-step
  • I/O assíncrono: Node.js brilha em cargas orientadas a I/O (múltiplas buscas Tavily paralelas com 512MB RAM)

Dívida técnica: Para embeddings locais e RAG avançado, criar um microserviço Python isolado invocado sob demanda via HTTP pelo Orquestrador TypeScript.

3.4 Por que PostgreSQL e não SQLite

  • Multi-usuário concorrente (múltiplos analistas simultâneos)
  • Fila assíncrona do KRONOS (cron jobs com cooldown)
  • Preparação para pgvector (embeddings/RAG no mesmo banco)
  • Deploy Docker simplificado (contêiner oficial PostgreSQL)

Motor de IA Multi-Agente

4.1 Arquitetura do Motor

O núcleo de IA vive em packages/core/:

  • Orchestrator.ts: Registra agentes, despacha execuções
  • Agent.ts: Executa um agente individual via generateText do Vercel AI SDK
  • types.ts: Contratos TypeScript (AgentContext, Tool)

O HERMES (orquestrador) usa consultar_agente para delegar. Os especialistas (SCOPUS, KLIO, etc.) usam web_search via Tavily. A delegação é sempre sequencial — um agente por vez.

4.2 Configuração Crítica do Agent.ts (sdk ai@6.0.168)

import { generateText, jsonSchema, tool, stepCountIs } from "ai";

// Parâmetros corretos no SDK v6:
const response = await generateText({
  model: anthropic("claude-opus-4-7"),
  system: this.systemPrompt,
  messages,
  tools: hasTools ? aiTools : undefined,
  stopWhen: stepCountIs(10),          // ← NÃO é maxSteps
  prepareStep: hasTools
    ? async ({ stepNumber }) => ({
        toolChoice: stepNumber === 0 ? "required" : "auto",
      })
    : undefined,
  maxTokens: 32000,
});

// Fix obrigatório para inputSchema (sem este, execute() nunca é chamado):
(myTool as any).inputSchema = () => jsonSchema(rawSchema as any);

4.3 Motor Dinâmico de Metodologias

  • Auto-seed: getOrSeedMethodology() popula o banco com 7 agentes + MSEF na primeira requisição
  • Orquestração dinâmica: chat.ts consulta a metodologia escolhida e instancia apenas os agentes vinculados em tempo de execução
  • Atualização de prompts: Cada requisição atualiza os systemPrompts no banco — o código é sempre a fonte da verdade
  • Engine Manager: Interface admin para instalar novos "Motores" (JSON com agentes e metodologias) sem novo deploy
  • SSE: Rota POST /api/v1/chat/stream envia eventos de progresso — qual agente está trabalhando — antes da resposta final

4.4 Guardrails Anti-Alucinação

Se o LLM tentar acionar um agente não registrado na metodologia ativa, a ferramenta consultar_agente intercepta, devolve mensagem de erro estruturada e instrui o modelo a corrigir autonomamente — sem crash.

Timeouts Nginx críticos

Análises completas levam ~97s. Sem os timeouts abaixo, o Nginx corta a conexão em 60s com HTTP 504:

location /api/ {
    proxy_pass http://api:3333/api/;
    proxy_http_version 1.1;
    proxy_read_timeout 300s;
    proxy_connect_timeout 300s;
    proxy_send_timeout 300s;
}
SSE e Nginx A rota /api/v1/chat/stream usa SSE (Server-Sent Events). O proxy_read_timeout 300s já cobre o tempo da análise. Não é necessário configuração adicional para SSE no Nginx com Hono.

O Que Deu Errado (Para Não Repetir)

8.1 — A Guerra de Instâncias Zod (Dual-Package Hazard)

SintomaErro tools.0.custom.input_schema.type: Field required da API Anthropic
CausaDuas instâncias físicas do Zod no monorepo — instanceof ZodObject retornava false
Solução definitivaAbandonar Zod completamente no Agent.ts. Schemas são objetos JavaScript puros embrulhados em jsonSchema() da Vercel

8.2 — Campo Errado: parameters vs inputSchema

SintomaTool calling não enviava input_schema para a Anthropic
CausaO adaptador @ai-sdk/anthropic lê tool.inputSchema, não parameters
Solução(myTool as any).inputSchema = () => jsonSchema(rawSchema as any);

8.3 — maxSteps silenciosamente ignorado no SDK v6

SintomaFerramenta era invocada mas não havia síntese — response.text vazio
CausaNo ai@6.0.168, maxSteps foi removido. Default é stepCountIs(1)
SoluçãostopWhen: stepCountIs(10)

8.4 — toolChoice: 'required' bloqueando a síntese

Sintomaresponse.text continuava vazio mesmo com loop correto
CausatoolChoice: 'required' se aplica a todos os steps — impede síntese
SoluçãoprepareStep: async ({stepNumber}) => ({ toolChoice: stepNumber === 0 ? "required" : "auto" })

8.5 — inputSchema com objeto bare (sem validate)

Sintomaexecute nunca era invocado
CausaObjeto bare sem validate() — o SDK chama asSchema() e valida os args. Sem validate, falha silenciosamente
SoluçãoRetornar jsonSchema() completo (com validate passthrough)

8.6 — Prompt HERMES com instruções contraditórias

SintomaHERMES ignorava a obrigação de usar ferramentas e respondia diretamente
CausaBloco [INICIALIZAÇÃO DA SESSÃO] com "NÃO USE FERRAMENTAS" vinha depois da regra "SEMPRE invoque consultar_agente", sobrescrevendo-a
SoluçãoReescrever o prompt com regra única, sem exceções, sem blocos contraditórios

8.7 — Histórico ilimitado encolhendo respostas a cada turno

SintomaRespostas de 5.000 chars na primeira mensagem → 2.000 → 500 → "Análise concluída."
CausaHistórico completo enviado para a API — contexto disponível para síntese ficava mínimo
Solução.slice(0, -1).slice(-12) — máximo de 12 mensagens

8.8 — CMD do Dockerfile rodando tsx em vez do dist/

SintomaApós rebuild limpo, erros de schema voltavam
CausaCMD ["npx", "tsx", ...] em produção — pacotes internos resolvidos pelo dist/ inconsistente
SoluçãoCMD ["node", "apps/api/dist/index.js"]

8.9 — .env com variáveis concatenadas na mesma linha

SintomaTAVILY_API_KEY inválida — HTTP 403 no Tavily
CausaVariáveis separadas por \n literal ficavam na mesma linha do arquivo
Diagnósticodocker exec olympus_api sh -c "printenv | grep -i tavily"

8.10 — Nginx com timeout padrão de 60s

SintomaHTTP 504 em análises completas (~97s). API gerava resposta com sucesso, cliente recebia 504
Soluçãoproxy_read_timeout 300s no bloco /api/ do nginx.conf

8.11 — maxTokens insuficiente truncando respostas

SintomaAgentes executavam buscas mas entregavam frases de desculpa
CausamaxTokens: 4096 não tinha espaço para a síntese final com contexto de busca
SoluçãomaxTokens: 32000 para etapa e thinking; 16000 para passagem

8.12 — Gauge SVG desenhando arco para baixo (fora do viewBox)

SintomaSemicírculo do gauge renderizado abaixo da viewBox (y>68) — invisível; apenas os endpoints ficavam visíveis
Causasweep-flag=0 (anti-horário) no SVG Arc percorre da esquerda para a direita passando pelo fundo (y=90), fora do viewBox de 68px de altura
Soluçãosweep-flag=1 (horário) → arco passa pelo topo. Ponto final em toXY(0.1°) em vez de toXY(0°) para evitar ambiguidade de arco de 180° exatos onde o browser pode escolher qualquer direção

8.13 — Relatório Padrão selecionando mensagem do THEMIS (Etapa 6)

SintomaAo gerar "Relatório Padrão", o PDF exportado mostrava o conteúdo do THEMIS (Etapa 6) em vez do relatório consolidado do HERMES
CausaO bloco "PONTO DE DECISÃO" do THEMIS Etapa 6 contém a string "RELATÓRIO FINAL PADRÃO" como opção ao usuário. A lógica antiga usava um fallback (hermesPool.length > 0 ? hermesPool : candidates) — quando nenhum relatório HERMES existia na sessão, selecionava qualquer mensagem com a string, incluindo a do THEMIS
SoluçãoHelper isHermes(content): verifica os primeiros 120 chars por **HERMES** excluindo HERMES_REVISOR. Fallback removido — sem HERMES real na sessão, exibe alert pedindo ao usuário concluir todas as etapas

⛔ Regras Críticas — Nunca Violar

9.1 — Zod não entra no Agent.ts

Sugestão a recusarPor que falha
parameters: z.object({...})instanceof falha entre pacotes no monorepo
maxSteps: NIgnorado silenciosamente no SDK v6 — usar stopWhen: stepCountIs(N)
toolChoice: 'required' sem prepareStepBloqueia síntese em todos os steps
inputSchema: { type: "object", ... } (JSON bare)asSchema() da Vercel rejeita JSON sem wrapper

✅ Único padrão correto:

parameters: jsonSchema(OBJETO_JS_PURO as any)
// + após criar o tool():
(myTool as any).inputSchema = () => jsonSchema(rawSchema as any);

9.2 — Prompt do HERMES — regra de ouro

Nunca adicionar blocos que isentem o HERMES de usar ferramentas. Qualquer instrução "neste caso não use ferramentas" conflita com a regra absoluta e o LLM seguirá a exceção. Se precisar de comportamento diferenciado por contexto, usar prepareStep no SDK — não o prompt.

9.3 — CMD em produção sempre aponta para dist/

# PRODUÇÃO (correto):
CMD ["node", "apps/api/dist/index.js"]

# DESENVOLVIMENTO (apenas local, nunca no Dockerfile):
CMD ["npx", "tsx", "apps/api/src/index.ts"]

11.1 — Fluxo Normal de Rebuild

# Após alterar API ou packages/:
docker compose build --no-cache api

# Após alterar apenas o frontend:

11.2 — Reset Nuclear

# 1. Zerar tudo
wsl --shutdown
docker compose down -v --rmi all
docker system prune -a -f --volumes

# 2. Reinstalar dependências
npm install

# 3. Build e subida completa
docker compose build --no-cache
docker compose up -d

# 4. OBRIGATÓRIO após -v: criar extensão e aplicar schema
docker exec olympus_db psql -U postgres -d olympus -c "CREATE EXTENSION IF NOT EXISTS vector;"
cd packages/db
npx drizzle-kit push
cd ../..

# 5. OPCIONAL — repovoar banco com agentes e metodologias
$env:DATABASE_URL = "postgres://postgres:postgres@localhost:5432/olympus"
npx tsx apps/api/src/scripts/seed.ts

# 6. Verificar saúde
docker compose logs -f api

13.1 Riscos Técnicos

Esgotamento do limite Tavily gratuito

ContextoPlano free: 1.000 req/mês. KLIO + KRATOS consomem buscas por análise. Com 2 clientes em monitoramento diário, o limite é insuficiente.
MitigaçãoMigrar para Tavily Starter (~USD 29/mês) após primeiro contrato. Incluir R$ 150/mês no modelo de custo. Brave Search API como fallback de custo zero.

Race condition DB→API no Railway (cold start)

ContextoRetry 10×3s funciona em Docker local. No Railway cold start, comportamento pode diferir — logs podem mostrar falha na conexão inicial.
MitigaçãoConfigurar health check no Railway. Testar startup script. Documentar logs esperados.

Context bloat em análises longas

Contexto.slice(-12) é arbitrário. Análises de 20+ turnos podem ter qualidade degradada mesmo com o fix aplicado.
MitigaçãoImplementar sliding window baseada em token count (tiktoken). Monitorar qualidade com análises longas antes de implementar.

Dependência Voyage AI (RAG)

ContextoPlano gratuito pode ser descontinuado. Não estava no orçamento original.
MitigaçãoEmbeddings locais com nomic-embed via Ollama como alternativa. Migração facilitada pela Provider Factory já implementada.
